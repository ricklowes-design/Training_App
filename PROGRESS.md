## Deviations
- 2026-10-30 STOP is press-and-hold (0.8 s) to stop accidental ends; it is not a confirmation dialog (audit task 13).
- 2026-10-30 Auto-pause when the page is hidden (audit task 11): a session pauses itself when the Chromebook's screen turns off, the lid closes or another tab is shown; it resumes only on a tap.
- 2026-10-29 Parent asked for a "turn on" button on every relevant drill: it is on the drill's instructions screen, before the block starts, which is a settings change during a session (plan/13.1 "no mid-session settings"). It is one optional tap, never required, and never shown once everything is on.
- 2026-10-27 Personal best for timed benchmarks: the plan does not say how to rank a faster run with more errors; the app ranks by fewest errors, then fastest, so a personal best is never bought with control errors and no combined score is formed.
- 2026-10-25 Movement data from the parent's own recordings is committed (joint positions only, approved by the parent); the videos, images and face detail stay out of the repository under the "nothing personal" rule.
- 2026-10-15 Experimental features beyond the plan's first build, at the user's request: speech digits, cone detection from the room photo, and a model-based ball detector (EfficientDet-Lite0 through MediaPipe, Apache-2.0: compatible with commercial distribution, so the licence check in CLAUDE.md is met). All are off by default and none can move a stage. The speech estimate covers the first 10 reps, matching the card's /10, although the block keeps cueing for its full time.
- 2026-10-15 Plan update: S3 stays in the content as an optional diagnostic and the sessions that used it run S2 instead (D8). The polygon-to-size rule (`polygonDims` in `src/domain/room.ts`) is a heuristic to scale drills, labelled approximate, to be tuned from the room checks. The Standard class uses the plan's default room (6.1 × 3 m) so default geometry did not change. Parent-entered tallies count as `verified` evidence; player-only tallies are `estimate`. Extended context fields are compared only when both results carry them, so trends from before the update continue. The 3D library assessment could not measure Chromebook performance here; the in-app measurement and the 2D/arrow fallbacks cover that until the parent runs it.
- 2026-10-14 Milestone 2 was built in the same session, before the milestone 1 acceptance, at the user's request. All camera numbers are unvalidated until the parent's checks above.
- 2026-10-14 Presence in the drill area (plan/14.6 item 4) is sampled live at 2 Hz from the same 64×36 motion picture as the tripwire, so completion is known at session end; the plan limits live camera use to the tripwire and framing check, and this is the same kind of pixel-motion check.
- 2026-10-14 MediaPipe Tasks Vision 0.10.35 is a dependency (allowed by CLAUDE.md for milestone 2). Its WebAssembly is served from the app (`/mediapipe/`), not precached for offline use; the pose models download from Google's storage on first use (allowed network calls).
- 2026-10-14 Camera set-up is in Parent mode rather than in the first-run set-up, since it needs the webcam mounted and the cones out.
- 2026-10-14 A rep where the camera saw no exit at all is "not judged" (flagged), not "wrong"; only cues whose right answer is to stay out of the gates are judged from no exit.
- 2026-10-14 Repository layout: this repository also holds an unrelated audit project, so the app lives in `home-training/` (with `CLAUDE.md`, `plan/`, `content/` beside it) rather than at the repository root.
- 2026-10-14 The whole of milestone 1 was built in one session at the user's request ("execute this plan"), not one task per session; each task's checks are listed above.
- 2026-10-14 Privacy: `plan/` contains the player's name and assessment. The repository is private, so it was kept as instructed, but GitHub Pages on a private repository needs a paid plan (plan/11 §11.4 VERIFY). Before making the repository public for Pages, remove `plan/` or deploy from a separate public repository containing only `home-training/` minus `plan/`.
- 2026-10-14 Content additions (version 0.2.0): structured data the code needs and the plan describes only in prose — drill `mode` (timed vs rep-based, for the 80% DONE rule), layout geometry, baselines (blocks, three parent questions, default start), placement proposal by yes-count, builder templates for 30/45/60 and light, the picture quiz, structured advancement rules (with parent checks for what numbers cannot show), a cue-accuracy benchmark `CA`, regressions for dribbling and ball control (the plan names none; placeholders for the coach), neutral templates (e.g. `result`, `firstResult`, `unlocked`, `reason`) and the core-move list for set-up.
- 2026-10-14 Stage boundaries: the first session of a new stage stays locked until the parent confirms the advancement (the plan's "Stage N unlocks after your parent confirms"); meanwhile the suggestion is to repeat the stage's last benchmark session as an extra.
- 2026-10-14 Builder: the plan gives templates only for 30 min/1 area, 45/2 and 60/3 (plus light 20). Other combinations are not offered; a coach can add templates to the content file. When a session has no benchmark, the benchmark slot repeats block A.
- 2026-10-14 Multi-area runs create one session record per area (sharing a run id); each area is judged by its own work blocks plus the shared warm-up and pauses.
- 2026-10-14 Anchor results are stored at layout version 0 ("anchor layout") because their conditions are fixed regardless of the room; A3 and A4 use cue level `manual-switchedon` until the cue engine exists.
- 2026-10-14 End-of-drill cards are shown after drill blocks (work, benchmark, anchor, quiz), not after warm-up, rests or cool-down.
